# Next.js Engine v2.6.2 — EngineScroll Consistency & Runtime Stability

> **Status:** Prepared bug-fix release  
> **Focus:** EngineScroll target semantics, viewport focus, resize correctness, SSR safety, URL behavior, snapping, and runtime isolation

v2.6.2 is a focused EngineScroll correctness release. It keeps the v2.6 shared-runtime architecture intact while fixing several places where navigation, ranges, timelines, browser lifecycle state, and scroll orchestration did not agree with each other.

---

## Release highlights

- `EngineScroll.timeline({ start: "#id" })` and `EngineScroll.range()` now accept ordinary DOM ids just like `EngineScroll.move("#id")`.
- Navigation, Range, and Timeline now share one `EngineScrollTargetResolver` implementation in `EngineScrollNavigator.ts`.
- Plain DOM range boundaries are resolved live so late mounts and dynamic layout movement cannot leave a stale/invalid range cached forever.
- `viewport.current` now defaults to progressive document-aware focus rather than permanent screen center.
- Added `EngineScroll.setFocus()`, `getFocus()`, and `getFocusMode()`.
- Resize/orientation events no longer destroy the previous measurement snapshot before geometry invalidation can compare it.
- Hash movement now fails safely during SSR.
- `#-es?` protocol matching no longer captures unrelated hashes beginning with `#-es`.
- Failed protocol movement no longer erases the URL before the target exists.
- Snap cleanup ownership and standalone directional snapping are fixed.
- Runtime subscriber failures are isolated so one consumer cannot starve the rest of EngineScroll.
- EngineScroll now actually runs its browser initialization policy, including manual browser scroll restoration.
- Scroll velocity/direction now follows the physical top scroll edge instead of the configurable logical focus point.

---

## 1. Range/Timeline DOM-id resolution fixed

Before v2.6.2:

```ts
EngineScroll.move("#hero");       // DOM id worked

EngineScroll.timeline({
	start: "#hero",
	end: "#features",
});                                // could remain invalid
```

`EngineScrollRange` stopped after registered-point lookup failed. Navigation already had a DOM fallback, so the public APIs had inconsistent `#...` semantics.

v2.6.2 uses one resolver path:

```text
number / top / bottom / current
        ↓
registered EngineScroll point
        ↓ when missing
normal DOM id
        ↓
alignment + offset resolution
```

Registered points still take precedence over a same-named DOM id.

---

## 2. Late-mounted and moving DOM boundaries fixed

A plain DOM boundary is not owned by `EngineScrollPointManager`, so the old registered-point revision cache could preserve:

- an initial `null` result before Suspense/lazy content mounted;
- old coordinates after a normal DOM element moved;
- an invalid timeline even after the matching id appeared.

v2.6.2 keeps registered points cached, but treats unregistered DOM ids as live geometry. The next Range/Timeline read sees the current element and current layout.

For very large orchestration graphs, registered points remain the preferred cached path.

---

## 3. Progressive `viewport.current`

The old default focus was permanently:

```ts
0.5
```

so `viewport.current` always sampled the middle of the monitor. On long pages, `source: "current"` could therefore begin several percent into a reading-progress timeline while the user was still visually at the document start.

The v2.6.2 default is:

```ts
"progressive"
```

using:

```ts
maximumScroll = Math.max(0, documentHeight - viewportHeight);
focus = maximumScroll === 0
	? 0
	: clamp(scrollY / maximumScroll, 0, 1);
```

That gives:

```text
document start   -> viewport focus 0.00
document 25%     -> viewport focus 0.25
document halfway -> viewport focus 0.50
document 75%     -> viewport focus 0.75
document end     -> viewport focus 1.00
```

### Public API

```ts
EngineScroll.setFocus("progressive");
EngineScroll.setFocus("top");
EngineScroll.setFocus("center");
EngineScroll.setFocus("bottom");
EngineScroll.setFocus(0.35);

EngineScroll.getFocus();
EngineScroll.getFocusMode();
```

Apps that intentionally depend on the historical center behavior can use:

```ts
EngineScroll.setFocus("center");
```

`viewport.top` and `viewport.bottom` remain exact physical viewport edges.

## 4. Resize geometry invalidation fixed

`BrowserEvents.onResize()` previously wrote new viewport/document dimensions into the cache before `EngineScrollBrowser.update()` ran.

That destroyed the old-vs-new comparison used to detect a geometry change and invalidate registered points.

Resize/orientation handlers now only schedule the shared update. `EngineScrollBrowser.update()` remains the single owner of browser measurement cache writes and invalidation.

---

## 5. SSR hash movement fixed

`EngineScrollHash.moveToHash()` previously touched `document` unconditionally.

It now returns `false` safely when `window`/`document` do not exist instead of throwing from a server path.

---

## 6. EngineScroll URL protocol collisions fixed

The old detector used:

```ts
hash.startsWith("#-es")
```

which could capture normal anchors such as:

```text
#-essay
#-eslint
#-esoteric
```

v2.6.2 only recognizes the actual protocol prefix:

```text
#-es?
```

---

## 7. Failed URL movement no longer destroys intent

The protocol previously cleaned the hash before checking whether the target actually resolved.

Now the URL is cleaned only after successful movement. If a lazy target does not exist yet, the protocol hash remains available instead of being silently discarded.

---

## 8. Snap ownership fixed

Before:

```ts
const stopA = EngineScroll.enableSnap({ group: "a" });
const stopB = EngineScroll.enableSnap({ group: "b" });

stopA(); // could disable B
```

Each snap session now owns a unique token. A stale disposer can only stop the session it created.

---

## 9. Standalone directional snap fixed

`EngineScroll.snap({ mode: "directional" })` previously depended on direction remembered by the auto-snap subscription. When auto snap was off, that value could remain zero and directional snap degraded into nearest-point behavior.

One-shot snap now uses current runtime direction when no remembered direction exists.

---

## 10. Runtime subscriber isolation

`EngineScrollRuntime.notify()` previously used one unguarded callback loop. A single throwing subscriber could prevent every later subscriber from receiving the frame and could bubble out through the shared scheduled update.

Subscribers are now isolated individually, and the current subscriber set is snapshotted before dispatch.

---

## 11. Browser initialization connected

`EngineScrollBrowser.initialize()` already contained browser policy setup such as manual `history.scrollRestoration`, but `EngineScroll.initialize()` never called it.

v2.6.2 connects that lifecycle. Public movement methods also initialize the Engine before attempting movement, making direct use more predictable.

---

## 12. Physical velocity semantics restored

With progressive focus, `viewport.current` can move inside the viewport as part of the focus strategy itself. Using it for scroll physics would mix logical attention movement into physical scroll velocity.

EngineScroll physics now measures from:

```text
viewport.top
```

so `velocity` and `direction` remain physical regardless of focus mode.

## Compatibility note

The default `viewport.current` behavior is intentionally different in v2.6.2. If your effect specifically uses `current` as a permanent center-of-screen probe, set:

```ts
EngineScroll.setFocus("center");
```

No schema migration is required for registered points, navigation, ranges, timelines, snapping, or Director tracks.

## Short release summary

**NE v2.6.2 makes EngineScroll consistent across navigation, ranges, timelines, DOM ids, registered points, viewport focus, resizing, URL navigation, snapping, and runtime subscribers — without replacing the shared-runtime model introduced in v2.6.**
